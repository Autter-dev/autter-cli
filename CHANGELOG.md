## [3.7.0] - 2026-11-12

### Fixed

- **The background service could stay up while dropping every checkpoint** (since 3.3.0). When it could not start a handler thread it retried forever, its health check still passed, and `autter checkpoint` exited 0 with nothing recorded. The service now stops and restarts after 20 failures in a row or 5 seconds without serving a connection, its health check needs a reply on the control socket (not just a connection), and running out of file descriptors counts as unhealthy on the first check. Idle control connections are closed after 10 seconds and handler threads are capped at 512, so held-open connections can no longer pin it at its thread limit.
- **Checkpoints are confirmed.** The service now acknowledges each checkpoint as soon as it has read it, before processing it. A hook waits up to 200 ms for that receipt and says on stderr when a checkpoint may not have been recorded (it still exits 0); a direct `autter checkpoint` exits 1 without one. An older service without receipts is detected and handled as before. Hook checkpoints are also faster (median 35 ms to 9 ms in a debug build). Windows gets the same handler-thread cap and at-capacity restart as macOS and Linux.
- **Attribution kept through more rebases.** AI lines became the user's when a branch renamed a file and an agent edited it again before the rebase, across a chain of renames, when a new file was later created at the old path, when the rename was folded into the AI commit as a fixup, and when a later commit on the branch rewrote the AI line. A rebased note could also drop a line added above an earlier line by the same author. An interactive rebase that reorders, squashes or drops commits now pairs each rebased commit with the commit it replays (from the notes git copies, then patch IDs), instead of by position.
- **Attribution kept through `cherry-pick -n` and `reset`.** `git cherry-pick -n A B` (or two `-n` picks in a row) carried only the last pick's AI lines into the commit; a conflicted `-n` pick that was resolved and committed by hand lost all of them, including files that merged cleanly; a `git reset` that left HEAD where it was could be recorded as a move from the branch visited before, so staged AI work was committed as the user's. A conflicted pick is now worked out from the commits rather than the index, so staging a resolution early no longer credits hand-resolved lines to the AI; `checkout --theirs` keeps the AI's picked lines; a pick that is stashed and never popped or thrown away with `checkout -- .` or `restore` no longer attaches to a later commit; and a known-human checkpoint after a pick no longer claims picked lines it did not change. `git stash branch` keeps attribution, and `git reset --hard` drops the uncommitted AI attribution of the work it threw away, so text retyped by hand is not credited to the AI.
- **`autter show-prompt` picked the wrong commit among commits made in the same second** when an unrelated commit shared the timestamp, and spawned one git process per comparison (81 same-second commits took over 40 seconds; now about 2.5). The order is now history order, with the smaller commit id first among unrelated commits.
- **Usage metrics queue.** Another queue recovering reset the metrics queue's learned batch size and backoff, so it went back to sending the batch that was timing out. A clock stepping backward could schedule the next attempt far in the future, and the backoff was measured from the start of a slow request instead of from its failure. A partial "retry later" answer now halves the next batch. Rows the server rejects every time no longer block the queue: after repeated identical failures they are set aside (kept, not deleted), shown in `autter doctor` and `autter sync status`, and re-queued with the new `autter sync retry`.
- **`autter doctor` restarted a service that was only slow.** One missed probe was enough, which dropped work in flight on a busy machine. Doctor now keeps probing with a longer limit and restarts only a service that stays unresponsive, and says how long it waited.
- **Two hook refreshes could run at once** after an upgrade and rewrite the same agent config files; the refresh is now claimed under a lock.
- **`install.sh` did not sign in after a failed install-token exchange.** The install command copied from the Autter app carries a one-time token; when exchanging it failed the installer continued signed out without saying so. It now starts `autter login` before onboarding, or names the command when there is no terminal.
- **`autter log`, `autter blame` and `autter show` in a repository with no commits** printed git's raw error; they now say the repository has no commits yet, as `status` and `stats` do.
- **Diagnostics read the service's pid file from the wrong folder** when socket paths were shortened, so the service's start time and the outdated-binary check were never seen.
- **`AUTTER_TEST_FORCE_TTY` was read in release builds**; it is now test-only.
- **An install of the npm package from a checkout** fetched the 3.1.0 binary, because the checked-in package version was stale. It now resolves the latest release.

### Changed

- **`--strict` exit 3 means autter has no record.** `autter stats --strict` and `autter status --strict` used to exit 3 for any commit with no AI or known-human lines, so CI failed on ordinary hand-typed commits. Exit 3 now means capture missed the change: the commit has no authorship record (the service was down, hooks were missing, the agent is unsupported, or the commit predates setup). A hand-typed commit with capture working exits 0, and its `capture.status` is `captured`. A merge commit is judged on the lines that are in none of its parents.
- **`autter status` counts the whole working tree**, including files git does not track yet and hand edits; its totals now match `git diff`.
- **Range stats call lines from a commit with no record `unknown`**, as single-commit stats and blame do, instead of `untracked`. Range stats and `autter log` print the unsupported-agent note.
- **`--json` prints one document on every failure path**, including when the background service is unreachable (new error code `service_unreachable`), for an unknown command, and for `autter sync <unknown>`. `autter log` with a flag git rejects exits 2 (`usage_error`) instead of 1; an unknown revision in `log`, `diff` and `blame --ignore-rev` reports `revision_not_found`. `autter sync --json` runs `sync status`, and `autter <unknown> --json` with the service down prints one `usage_error` document.
- **`autter bg status` and doctor's service check need a reply**, so a service that accepts connections but does not answer is reported as unhealthy.
- **Windows start-up (not yet verified on a Windows machine):** longer waits for the service's first readiness and for the trace2 probe, a service that is up but has not processed an event yet is no longer reported as a failed start, a lock file left by a service that died is taken over, and a lock held by a service started from an Administrator window gets the elevated-service fix text.

### Added

- **`autter doctor --report <file>`** writes one support file: doctor results, measured timings, service and lock-file state, the last 200 lines of the service log, OS and git versions, and whether the process is elevated. Free text is redacted the way `autter debug` output is.
- **`install.ps1` dry run, progress and npm fallback.** `$env:AUTTER_INSTALL_DRY_RUN = '1'` prints what the Windows installer would do and changes nothing; the binary download shows progress at a terminal; a failed download names the URL and the npm route.
- **`autter blame --json` gives every line a category** (`line_categories`, `category_counts`), with the same names the other commands use, and session prompts' `accepted_lines` now match the commit's note.
- **`autter sync retry`** re-queues usage-metrics events that were set aside.
- **INSTALL.md says where autter is installed and why the location is fixed** (`~/.autter/bin`), and how to make `autter` available elsewhere.
- **CI:** a daily install smoke test that runs the documented install commands on macOS, Ubuntu and Windows, and a job that runs the npm launcher's tests.

## [3.6.0] - 2026-11-11

### Added

- **`install.sh --dry-run`**: `curl -fsSL https://api.autter.dev/install.sh | bash -s -- --dry-run` (or `AUTTER_INSTALL_DRY_RUN=1`) prints what the installer would download, write and start, and changes nothing. The installer also shows a progress bar for the binary download when run in a terminal, and names the npm route (`npm install -g @autter/cli && autter onboard`) when a download from GitHub fails. Unknown installer options are now an error (exit 2).
- **Onboarding ends with what it changed**: `autter onboard` closes with a list of what setup changed on this machine and the command that undoes it, and says that discarding the queued backlog is permanent.
- **`docs/background-service.md`**: what the background service does, what it listens to and how to debug it. `INSTALL.md` now says which install to use where (macOS, Linux, Windows, WSL, CI), and covers npm 10+ blocking install scripts, `npm update` not upgrading the CLI, and PowerShell's "not recognized" error.

### Changed

- **`autter doctor` names one root cause before setup**: on a machine where setup never ran, doctor prints a single "Root cause" line and "Next step: run `autter onboard`" instead of a list of dependent failures. In local mode the sign-in and upload checks are skipped instead of shown as warnings. A JetBrains IDE without the autter plugin is a warning, not a failure. A repository rooted at the home folder is a warning. Check time limits grow on machines where git itself is slow (`AUTTER_DOCTOR_TIMEOUT_SCALE` sets the scale by hand).
- **Superuser warning**: shown in full once a day and as one line otherwise, and not at all with `AUTTER_ALLOW_SUPERUSER=1`.
- **Background self-update holds in CI, for a pinned release and with `AUTTER_DISABLE_AUTO_UPDATES=1`**, so a pinned `@autter/cli` version is not replaced under a CI job.
- **CI compiles the Windows binary on every pull request.** Until now the first Windows compile was the release build, after the tag.

### Fixed

- **`curl … | sh` on Debian and Ubuntu**: the installer stopped with `set: Illegal option -o pipefail` because `sh` is dash there. Run as a file it now hands over to bash; piped to `sh` it says to run the same command with `bash` and changes nothing.
- **`autter uninstall` deleted the user's whole `[trace2]` git config section**; it now removes only the settings autter wrote.
- **`autter status` and `autter stats` in a repository with no commits** printed git's raw error; they now say the repository has no commits yet.
- **Credentials file errors name the file**, with what to do about it.
- **Windows: no more VS Code windows opened by `onboard`, `doctor` and `uninstall`** when `Code.exe` comes before `bin\code.cmd` on PATH. autter now runs the editor's command line (`bin\code.cmd`, or `cli.js` with `ELECTRON_RUN_AS_NODE`), treats an empty `--version` as an error and stops calling the editor for the rest of the command. A version doctor cannot read is reported as unknown instead of "predates native agent hooks".
- **Windows: an antivirus block or an elevated background service is named**: when Windows refuses to start the service (os error 225) or denies access to one started from an Administrator window, `autter bg start/restart` and `autter doctor` say so with the steps to fix it, instead of advising another restart.
- **npm on Windows: `spawnSync autter.exe UNKNOWN`** is followed by the likely causes (antivirus, incomplete download, wrong processor type) and the commands that check and fix each.

These Windows fixes are unit-tested and compile on Windows in CI, but have not been run on a Windows machine.

## [3.5.1] - 2026-11-11

### Fixed

- **A moved autter binary is caught for Claude Code, Droid, Gemini, Firebender and Windsurf**: these agents' hooks counted as up to date whenever an autter checkpoint command was present, whatever binary it named. When the binary moved (a nix store path, a dev build, a renamed home directory), the refresh after an upgrade skipped them and `autter doctor` reported "hooks installed (up to date)" while the agent ran a command that no longer existed and nothing was captured. The refresh now rewrites those commands, and `autter doctor` fails for the agent with the command that cannot run. The refresh still starts only when the CLI version changes; after moving the binary without upgrading, run `autter install-hooks`.
- **`autter --json uninstall-hooks` no longer starts a hook refresh**: the first command after an upgrade refreshes agent hooks in the background, except for commands that install or remove hooks themselves. That exception looked at the first argument only, so a global flag in front (`--json`, `--quiet`, `--no-color`, `--strict`, `-C <path>`) let a refresh run beside `install-hooks`, `uninstall-hooks`, `uninstall`, `upgrade` or `onboard` and rewrite the files they were changing.
- **A hook that names a command this autter does not have no longer blocks the agent**: after a downgrade, or once a command is renamed, an agent hook could run `autter <unknown> … --hook-input stdin`, which exited 2, the exit code Claude Code treats as "block the tool call". It now prints `{}`, says on stderr that the hook is out of date and how to refresh it, and exits 0, also when the background service is unreachable. An unknown command typed by a person still exits 2.

## [3.5.0] - 2026-11-11

### Added

- **Scriptable CLI for CI**: `--json` on every reporting command (`stats`, `status`, `log`, `show`, `blame`, `diff`, `whoami`, `doctor`, `sync status`), each document with `schema_version` and, on failure, an `error` object; documented exit codes (0 success, 1 runtime, 2 usage/outside a repo, 3 nothing captured, 4 capture broken); `--strict`/`AUTTER_STRICT=1` so `stats`/`status` fail when nothing was captured and `doctor` when capture is broken; no color, prompts or spinners when `CI` is set. ## [3.4.1] - 2026-11-09

### Fixed

- **Usage metrics no longer get stuck**: a metrics queue could stop draining for good because every retry sent the same 1,000-event batch and timed out the same way. A timeout or HTTP 413/504 now halves the next batch (growing back after five successes), failures back off from 5 seconds up to 15 minutes, and a failed request ends the pass. See [changelog/usage-metrics-queue-drains.md](changelog/usage-metrics-queue-drains.md); the server-side changes described there ship separately.
- **`autter doctor` says why metrics aren't uploading**: a separate "usage metrics upload" check names `POST /worker/metrics/upload`, the error (e.g. "timeout after 30s"), the attempt count and the next retry, says attribution is not affected, and is a warning, not a failure. It never suggests restarting the service. The durable sync queue check counts only attribution queues.
- **Metrics failures aren't reported as attribution failures**: they no longer trigger the post-commit "Cloud sync is failing" warning or make `autter sync status` report upload failing. `sync status` shows usage metrics on their own line (`--json` adds `usage_metrics`), and `autter sync purge` also resets the metrics state.

## [3.4.0] - 2026-11-09

### Added

- **Authorship categories, explained the same way everywhere**: `stats`, `blame`, `show`, `log` and `status` use one set of labels — AI, human, untracked (Autter recorded the commit but nothing recorded the line, usually typed by hand) and unknown (the commit has no Autter record). `autter stats` prints each category's line count and share and one line on what the AI share measures. `autter blame` on a terminal starts each line with its category and ends with a legend; piped output is unchanged (`--markers` / `--no-markers`). See [changelog/authorship-categories-explained.md](changelog/authorship-categories-explained.md).
- **Why a commit has no attribution**: instead of five repair commands, `stats`, `show` and `log` say which case applies — no AI activity, still being written, predates Autter, capture failed, made by someone else, or made while Autter was not recording — with at most one next step. A commit typed by hand no longer gets a troubleshooting block in `autter log`.
- **`autter stats --coverage [range]`**: how many commits have a record, are pending, predate Autter or are missing one and why, and whether records are on the remote.

### Fixed

- **No more wrong numbers right after a commit**: `stats`, `show` and `log` wait up to 10 seconds while the background service is still writing the commit's record, and `autter status` waits up to 3 seconds for queued checkpoints and says when some are still being written.
- **`autter stats A..B` piped**: printed only blank lines; it now prints the summary and counts known-human lines in a range as human.
- **A note's `accepted_lines`** counted AI lines that were never committed; it now matches `stats --json` `ai_accepted`.
- **`show-prompt` with commits made in the same second**: the latest occurrence and `--offset` follow history instead of an arbitrary order (a rebase or script makes several commits per second).
- **Outside a repository**, repository commands print one plain sentence instead of git's `rev-parse` failure.

`stats --json` keeps its fields and adds `record`; `status --json` adds `pending_checkpoints`.

## [3.3.0] - 2026-11-09

### Added

- **From a line to the prompt that wrote it**: `autter blame` on a terminal (and with `--show-prompt`) ends with a legend of the prompts behind its AI lines — a short reference such as `s_3f9a2c1d`, the agent, model and lines. `--show-prompt` puts that reference on each AI line. `blame --why` prints the reference, the agent's own session ID, the commit and the exact `show-prompt` command, and says why a transcript can't be shown. `autter show-prompt` accepts the short reference, any unique prefix of 4+ hex characters, a full session ID or the agent's session ID, and lists candidates when a prefix is ambiguous. Piped blame output is unchanged.

### Fixed

- **The model is recorded on every checkpoint**: Claude Code sessions showed `unknown-model` after several consecutive writes, and VS Code Copilot edits nearly always did. Claude Code now takes the model of the message that made the edit, Copilot reads it from its chat session, and every agent remembers the last known model per session, so an unknown model never replaces a known one. Notes already committed are not rewritten.
- **Stale agent hooks never block the agent**: a hook autter can't run as written now exits 0 with "autter hook is out of date. Run `autter install-hooks`" instead of failing, and Google Antigravity always gets its JSON reply. After an upgrade, autter refreshes the hooks of agents you already set up, and `autter doctor` reports hooks that fail on every run as Failed, naming the agent and command.
- **`cherry-pick -n` and renames in rebases — 3.2.2 did not fully fix these**: attribution was still lost when `cherry-pick -n` was followed by a plain `git commit`, when the picked change landed on live AI work in the same file, and when a rebase replayed commits that rename a file. All three now keep attribution.
- **The background service stays up when the machine is busy**: one refused health-check connection, or one failure to start a handler thread, no longer shuts the service down.
- **`install-hooks` and `uninstall-hooks` return usage errors** instead of exiting the process on an unknown flag.
- **Telemetry docs say what it does**: error telemetry is off until you opt in.

## [3.2.2] - 2026-11-08

### Fixed

- **`autter checkpoint` tells the truth**: run by hand, it exits non-zero with the fix when capture can't work (git trace2 not configured, service unreachable, not in a repository). Checkpoints run by agent hooks still exit 0, so an agent is never blocked.
- **A human line stays human when someone appends below it**: when a file's last line had no trailing newline, an AI append made that line look rewritten, so blame showed the AI (e.g. GitHub Copilot) on both lines while stats was right. Gaining a line ending no longer changes a line's author.
- **The background service never inherits cloud-agent markers**: `autter bg restart` and `autter doctor` start it with a clean environment, and doctor adds the agent-detection variables to git's trace2 config on older installs so detection is per commit.
- **Renames inside rebased commits**: attribution follows a file renamed within the commits being rebased, including chains of renames.
- **`cherry-pick -n` onto uncommitted AI work**: the next commit merges the picked attribution with your live AI work instead of dropping it.

## [3.2.1] - 2026-11-08

3.2.0 was tagged but never published: its release builds failed. 3.2.1 is the same release with that build fixed.

### Fixed

- **Setup only says "all set" when capture works**: onboarding, `autter install --system` and the installers now verify capture end to end (background service, git trace2 config, a live git event) and report "mode saved" and "capture verified" separately. Skipped steps, trace2 write errors and service restart timeouts are reported with the command that fixes them. Your existing `[trace2]` git config is merged, not replaced. Doctor, whoami and status agree on whether cloud upload is on.
- **`--help` never runs a command**: `-h`/`--help` is answered for every command before anything else runs, so `autter uninstall --help` no longer uninstalls. Unknown flags are rejected. `autter uninstall` asks for confirmation (or `--yes`), prints only what it actually removed, and also removes the VS Code and Cursor extension.
- **No attribution lost while the background service is down**: a commit made while the service was stopped, starting, hung or unreachable is recovered from its checkpoints when the service is back, or written by the git proxy directly. Doctor checks for missed commits and rebuilds them, `checkpoint` warns when git capture isn't configured, and API outages read as temporary instead of bare 5xx errors.
- **Human edits no longer credited to a cloud agent**: background-agent detection now reads the committing command's environment instead of the background service's, and the broad `CLOUD_AGENT_*` prefix rule is gone, so one stray variable can't mark every commit as an agent's.
- **Shell edits by agents are attributed**: lines an agent writes with a shell command (`echo >>`, `sed -i`, a formatter) are credited to the agent even when the service restarted mid-call or the file was just edited. Doctor and `autter debug` say whether shell edits are captured.
- **VS Code Copilot agent edits are captured**: edits made by Copilot's agent mode in VS Code were dropped when VS Code sent no transcript path. Doctor now reports whether Copilot hooks are installed and when the last Copilot edit was captured.
- **Attribution survives history rewrites**: `git mv`, rebases (including onto a branch that renamed the file), cherry-pick ranges, `cherry-pick -n`, conflicted cherry-picks finished with `git commit`, and `--continue` after a restart. Plain `git fetch` now imports teammates' notes, and `git push` waits briefly so a just-made commit's note goes with it.
- **Connected mode keeps local notes**: connected mode now writes `refs/notes/ai` locally as well as syncing to the dashboard, and existing connected setups switch over automatically. Notes made earlier that only exist in the upload queue are copied into git once per repository; `autter notes backfill` does it on demand.

See [changelog/3.2.1-capture-and-setup-reliability.md](changelog/3.2.1-capture-and-setup-reliability.md).

## [3.1.0] - 2026-11-08

### Fixed

- **Repositories no org has connected stay on your computer**: in connected mode, authorship notes, commit summaries (with their prompts), file-change counts and prompt transcripts from a repository that none of your orgs has connected were uploaded to the org you signed in to — so a personal or client repository's prompts could show up in a workplace dashboard. ## [3.0.0] - 2026-11-04

### Added

- **`autter badge`**: a README badge with the share of the repository's added lines written by AI, `AI-written | 72%`. It prints the share over the last 90 days (`--since`, `--all-time`), how many commits had authorship notes, and a Markdown snippet it also copies. Repositories linked to Autter get a live badge that stays current; others get a shields.io badge, and `--write` stores an endpoint file (`.autter/badge.json`) that keeps it current from the repository itself. `--json` prints that payload. Prompt text stays on the machine unless you pass `--include-prompt-text`. See [changelog/wrapped.md](changelog/wrapped.md).

## [2.4.0] - 2026-11-03

### Added

- **Repository memory before code**: `autter install` adds an `autter memory-hook` next to the checkpoint hooks of Claude Code, Codex, Gemini CLI, Droid, GitHub Copilot and Cursor, and plugins for OpenCode, Amp and Pi. The agent gets the repository's shared memory when the session starts, the sections that match each prompt, and the area page for each file it reads or edits. The hook gives up after 3 seconds and prints nothing on any failure. Turn it off with `autter config set feature_flags.memory_context false`. See [changelog/memory-before-code.md](changelog/memory-before-code.md).
- **`autter memory`**: `autter memory search "<question>"` ranks the repository's memory, learnings, production lessons, team rules, past findings, wiki and code by meaning. `autter memory for <file>...` prints the area pages for the files you're about to edit, and `show`, `areas` and `ledger` read the rest. Add `--json` for scripts and agents. See [changelog/repository-memory-search.md](changelog/repository-memory-search.md).
- **`autter context "<task>"`**: everything Autter knows that matters for a task in one call: memory facts, wiki pages and code structure, ranked and cut to a token budget, with the fact ids to cite. It returns the same answer as the `get_context` MCP tool, for agents that aren't connected to it. See [changelog/agent-context-and-mcp-connect.md](changelog/agent-context-and-mcp-connect.md).
- **`autter memory skills install`**: writes the repository's own memory skill and a Cursor rule into the checkout, generated from its memory facts, so every teammate's agent has the memory with or without the CLI. `autter memory skills preview` prints them and writes nothing.
- **`autter mcp connect`** and **`autter mcp disconnect`**: add or remove Autter's MCP server in the user config of Claude Code, Codex, Cursor, VS Code, Gemini CLI and OpenCode. Only the URL is written, and the server signs you in with OAuth the first time an agent uses it. Every file is backed up before it changes.

### Changed

- **Repository memory skill**: the skill moved to `autter-repo-context` in [Autter-dev/autter-skills](https://github.com/Autter-dev/autter-skills), so agents without the CLI's hooks get it too. It tells agents to call `autter context` first, or `get_context` when the MCP server is connected, and to cite the fact ids they rely on.

## [2.3.0] - 2026-10-25

### Added

- **Redesigned setup**: `autter onboard` opens with the autter logo and walks one step rail with numbered questions ("2/4"). Each answer collapses to a single line, and the closing summary lists anything that needs attention with the command that fixes it. See [changelog/redesigned-onboarding-and-sign-in.md](changelog/redesigned-onboarding-and-sign-in.md).
- **Sign-in screen** (`autter onboard`, `autter login`): the one-time code and a live "expires in m:ss" countdown. Enter reopens the browser, `c` copies the code, and Esc continues in local mode (or cancels `autter login`). If sign-in fails you can try again, paste an access token (masked and checked before it's saved), or continue locally.
- **Per-tool integrations**: onboarding lists the coding tools it finds plus git capture, all checked, and installs only what stays checked. `--yes` still installs everything.
- **`autter stats -i`**: browse the last 200 commits by AI share, with each commit's AI, human and untracked lines and its breakdown by tool and model. See [changelog/status-screens-and-interactive-views.md](changelog/status-screens-and-interactive-views.md).
- **`autter blame -i <file>`**: read a file with a colored mark beside every line (AI, human, untracked), details for the line under the cursor, `n`/`N` to jump between AI changes, and Enter to see the prompt behind an AI line.

### Changed

- **Bare `autter`** at a terminal shows a status card: mode and account, the latest commit's AI share and tool, pending uploads, and commands to try. `autter help` lists every command.
- **`autter whoami`** at a terminal shows a card with your account, how long the session stays valid, organizations, cloud sync and API. **`autter doctor`** shows a spinner per check that resolves in place. **`autter install-hooks`** lists tools on a rail with a closing count. Piped and `--json` output of all three is unchanged.
- **One look everywhere**: prompts, spinners, the update prompt and every screen above share one theme in the autter teal, with ASCII and half-block fallbacks for legacy Windows consoles, plain lines for narrow or non-interactive terminals, and `NO_COLOR` / `--no-color` honored throughout.
- **Prompts**: arrow keys, j/k and Enter as before. Esc now cancels like Ctrl-C, and the 1–9, Tab and Space shortcuts in single-choice prompts were removed.

## [2.2.1] - 2026-10-18

### Fixed

- **A dead login is no longer retried**: when the server refuses the stored refresh token (`invalid_grant` or `login_required`), autter records the refusal with the credentials and stops refreshing until `autter login` stores new ones, instead of retrying on every daemon tick. Before giving up it uses a token that another autter process has just rotated in. Personal access tokens and temporary errors (network, 5xx, `temporarily_unavailable`) are retried as before.
- **One notice instead of a warning every few seconds**: interactive commands show the server's message (run `autter login`) once, and the daemon logs one warning per refusal.
- **A stale refresh can't overwrite newer credentials**: after a refresh, the stored credentials are replaced only if they still hold the refresh token that was sent, and a refresh waits up to 10 s for another process's refresh before going ahead without the lock.
- **OAuth errors keep their details**: token errors are parsed (`error`, `error_code`, `login_required`) instead of being flattened into a string, so callers can act on them.

## [1.5.9] - 2026-06-18

### Added

- **Telemetry Streams System**: New transcript-based telemetry system for improved session tracking and metrics
  - New `transcripts.db` database for managing AI agent sessions and watermarks
  - Unified `WatermarkStrategy` abstraction supporting multiple tracking methods (byte offset, record index, timestamp, hybrid)
  - Long-lived `TranscriptWorker` in daemon with polling-based modification detection
  - Incremental historical transcript processing for existing sessions
  - Session/trace ID linking in metrics events for server-side correlation and analysis
  - Trailing message capture: messages after last tool call are now recorded in telemetry
  - Support for multiple agent formats: Claude Code, Cursor, Droid, GitHub Copilot
- **Enhanced Metrics Schema**:
  - `session_id` field added to all metrics events (required, unique per agent conversation)
  - `trace_id` field added to checkpoint and commit events (nullable, links related operations)
  - `tool_use_id` field added to checkpoint events (nullable, tracks specific tool invocations)
  - Enables server-side analysis of conversation flows, tool usage patterns, and session lifecycles

### Changed

- **Internal DB Migration**: Existing `internal.db` installations automatically migrate to `transcripts.db` on daemon startup
  - Historical prompt records are converted to session records
  - Watermarks initialized for incremental processing of existing transcripts
  - `internal_db` module retained for backward compatibility but marked deprecated

### Deprecated

- **`internal_db` module**: Now deprecated in favor of `transcripts` module
  - All new installations use `transcripts.db`
  - Existing installations migrate automatically
  - Module retained only for migration purposes

### Technical Details

- **Architecture**: Three-component design with transcripts module, TranscriptWorker daemon task, and enhanced metrics schema
- **Processing Model**: 1-second polling interval for transcript modifications, priority queue for checkpoint notifications
- **Watermarking**: Per-agent configurable strategies handle diverse transcript formats (append-only JSONL, SQLite databases, etc.)
- **Migration Safety**: Automatic and idempotent, preserves all historical data

For detailed design rationale and implementation notes, see `docs/superpowers/specs/2026-04-29-telemetry-streams-design.md`.

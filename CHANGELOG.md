# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

This changelog is automatically generated by AI when releases are published.

## [Unreleased]

### Added

- **npm distribution**: `npm install -g @autter/cli` (and `npx @autter/cli`) now works via a thin bootstrapper package that downloads the checksum-verified release binary into `~/.autter/bin`, published automatically by the release workflow.

- **`autter blame --why <file>:<line>`**: Jump from a line directly to the prompt that produced it.
  - For AI-attributed lines: prints the agent name, model, human author, prompt hash, any issue/PR links from `custom_attributes`, and the resolved prompt transcript (user/assistant turns from the local CAS cache, sync queue, or cloud).
  - For human-authored lines: reports that no AI prompt is associated with the line.
  - `--open` flag: opens the most relevant URL (issue/PR from `custom_attributes`, falling back to the `messages_url`) in the system browser.
  - Clear errors for out-of-range line numbers and malformed `<file>:<line>` arguments.

- **Telemetry Streams System**: New transcript-based telemetry system for improved session tracking and metrics
  - New `transcripts.db` database for managing AI agent sessions and watermarks
  - Unified `WatermarkStrategy` abstraction supporting multiple tracking methods (byte offset, record index, timestamp, hybrid)
  - Long-lived `TranscriptWorker` in daemon with polling-based modification detection
  - Incremental historical transcript processing for existing sessions
  - Session/trace ID linking in metrics events for server-side correlation and analysis
  - Trailing message capture: messages after last tool call are now recorded in telemetry
  - Support for multiple agent formats: Claude Code, Cursor, Droid, GitHub Copilot
- **Enhanced Metrics Schema**:
  - `session_id` field added to all metrics events (required, unique per agent conversation)
  - `trace_id` field added to checkpoint and commit events (nullable, links related operations)
  - `tool_use_id` field added to checkpoint events (nullable, tracks specific tool invocations)
  - Enables server-side analysis of conversation flows, tool usage patterns, and session lifecycles

### Changed

- **Internal DB Migration**: Existing `internal.db` installations automatically migrate to `transcripts.db` on daemon startup
  - Historical prompt records are converted to session records
  - Watermarks initialized for incremental processing of existing transcripts
  - `internal_db` module retained for backward compatibility but marked deprecated

### Deprecated

- **`internal_db` module**: Now deprecated in favor of `transcripts` module
  - All new installations use `transcripts.db`
  - Existing installations migrate automatically
  - Module retained only for migration purposes

### Fixed

- **Unix installer PATH activation**: the installer now writes sourceable `~/.autter/env` / `~/.autter/env.fish` files that rc files point at, prints one always-works activation command (`source "$HOME/.autter/env"`) as its final output, and configures both `~/.bashrc` and `~/.bash_profile` when both exist — fixing `autter: command not found` in already-open terminals after following the printed guidance.
- **`autter ci` workflow templates** installed from the retired `autter.dev/install.sh` URL (which serves HTML); they now use `api.autter.dev/install.sh`.

### Technical Details

- **Architecture**: Three-component design with transcripts module, TranscriptWorker daemon task, and enhanced metrics schema
- **Processing Model**: 1-second polling interval for transcript modifications, priority queue for checkpoint notifications
- **Watermarking**: Per-agent configurable strategies handle diverse transcript formats (append-only JSONL, SQLite databases, etc.)
- **Migration Safety**: Automatic and idempotent, preserves all historical data

For detailed design rationale and implementation notes, see `docs/superpowers/specs/2026-04-29-telemetry-streams-design.md`.

## [2.0.1] - 2026-09-17

### Fixed

- **Git notes install**: `autter install-hooks` now sets `notes.rewriteRef` / `notes.displayRef` to `refs/notes/ai`, so rebase/amend no longer look half-installed when attribution already works.
- **Login fallback**: failed device login (including `autter onboard --connect`) prints a clear “paste an access token” next step via `autter login --token`.
- **Update notices**: when a newer release is available, the CLI always prints an upgrade nudge (not only when auto-updates are disabled), and checks for updates on git commands — not only on push.

### Changed

- Soft update nudge and platform `min_version` warnings remain the way older installs learn they should run `autter upgrade`.

## [2.0.0] - 2026-09-17

### Changed

- **Consent-gated system integrations**: npm / shell installers no longer mutate global git config, install IDE hooks, or start the daemon automatically. Those steps run during `autter onboard` (with consent) or via explicit `autter install --system`.
- **`autter uninstall`**: removes IDE/agent hooks, clears global git `trace2` config, and stops the background service.
- **`autter stats --wait[=secs]`**: polls for the authorship note before printing stats (default 30s); exits non-zero with a pending message if the note is not ready — safer for CI.
- **`autter sync purge`**: discards the local cloud-upload backlog without uploading it. Onboard offers Import vs Discard when connecting with a pre-existing queue.

### Fixed

- **`autter doctor` in local mode**: durable sync queue and expired/blocked cloud credentials no longer fail the run (warnings instead), so doctor can be used as a CI gate offline.
- **Windows checkpoint round-trip**: longer attribution self-check budget and a fresh warm-daemon probe deadline, addressing `timed out after 0.0s` false failures.
- Doctor remediations now name real commands (`autter install --system`, `autter daemon restart`).

## [1.7.6] - 2026-09-17

### Improved

- **Attribution troubleshooting**: `autter doctor` / `autter debug` now print a likely cause and concrete next step for checkpoint round-trip failures (persistence vs notes/blame vs permissions), and correlate with failed trace2 checks. Missing-authorship footers in `diff` / `blame` / `show` / `stats` point at `install-hooks` → `install` → `doctor` → `daemon restart` → `debug`. See INSTALL.md troubleshooting.

## [1.7.5] - 2026-09-12

### Fixed

- Windows ARM64 release builds: configure the amd64_arm64 MSVC environment and run that job on `windows-2022`, so link.exe no longer picks x64 SDK/MSVC libs (LNK4272 / LNK1120) after the Blacksmith runner migration.

## [1.7.4] - 2026-09-12

### Changed

- Browser device authorization now identifies itself as Autter CLI authorization and shows explicit successful, completed, denied, expired, and action-failed states.
- Terminal login now reports `CLI authorization successful` only after credentials are safely stored; failures state whether credentials were issued or changed.

### Fixed

- Automatically created version tags now explicitly dispatch the release workflow, avoiding GitHub's suppression of follow-on workflow events created with `GITHUB_TOKEN`.

## [1.7.3] - 2026-09-12

### Changed

- **`autter login` is interactive.** Running it without `--token` starts the browser device-authorization flow: Autter opens the approve page, shows a one-time code, and stores credentials when you confirm the device. `--token` remains the non-interactive PAT fallback for CI.

### Fixed

- A concurrent access-token refresh from the git proxy and the background service could rotate away the only stored refresh token and make cloud sync look like the login had expired. Refresh is now serialized across processes, and a lost race reloads the session the sibling already wrote.

## [1.7.2] - 2026-09-08

### Added

- Local capture and cloud upload status in `autter status` and interactive commit output.
- Confirmed metrics upload receipts and queue availability in sync status.
- `autter sync open` to open the provenance dashboard for the reported organization.

### Fixed

- Missing credentials, stopped services, and unreadable queues no longer appear healthy.
- Rejected metrics remain queued for retry without blocking newer records.
- Successful uploads from other queues no longer hide metrics upload failures.
- `autter sync` without a subcommand now shows status.

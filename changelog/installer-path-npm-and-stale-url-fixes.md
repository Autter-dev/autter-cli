# Unix PATH Activation, npm Distribution & Stale Installer URLs

## Summary

Three install-experience fixes, all reported against the very first interaction a new user has with autter:

1. **Unix installs left `autter: command not found` even after following the printed guidance.** The installer appended a raw `export PATH=...` line to detected rc files and told users to source those rc files. That guidance is unreliable: the edited rc can belong to a different shell than the one open, rc files can rebuild PATH or early-return before reaching the appended line, bash caches failed command lookups in its hash table, and the guidance itself scrolled out of view behind onboarding output — so users saw the fix only after opening a completely fresh terminal.
2. **No npm distribution.** `npm i -g autter` and `@autter/cli` both returned E404, leaving Node-centric teams without their native install path.
3. **The `autter ci` workflow templates still curled `https://autter.dev/install.sh`,** which now serves the marketing site's HTML instead of the installer (the canonical URL moved to `api.autter.dev`). Every CI pipeline generated from those templates piped HTML into bash.

## Changes

### `install.sh`

- **Sourceable env files** (the rustup/uv pattern): the installer now writes `~/.autter/env` (POSIX shells) and `~/.autter/env.fish`, which idempotently prepend `~/.autter/bin` to PATH and run `hash -r` so bash drops stale lookup caches. Shell rc files get a one-line `. "$HOME/.autter/env"` (or the fish `source` equivalent) with `$HOME` kept literal, instead of an expanded raw export.
- **One always-works activation command** — `source "$HOME/.autter/env"` — is now the installer's *final* output, printed after onboarding so it is the message left on screen. It is suppressed when the inherited PATH already resolves autter (upgrades). The per-rc-file "source this file" list is gone.
- **bash login-shell coverage**: when both `~/.bashrc` and `~/.bash_profile` exist, both are configured. Login shells (macOS Terminal/iTerm, SSH) read the profile while interactive non-login shells read bashrc; double-sourcing is harmless because the env file dedups.
- **Re-run idempotence across generations**: the append guard recognizes both the new env-source lines and the legacy raw-export lines from older installers.
- **/dev/tty probe fixed**: `[ -r /dev/tty ]` passes without a controlling terminal and then printed a bare `/dev/tty: Device not configured` error; the installer now actually opens the device to decide how to run onboarding.

### `npm/` (new) + `.github/workflows/release.yml`

- New `autter` npm package: a thin bootstrapper whose postinstall downloads the official release binary into `~/.autter/bin` — the same canonical location the shell installers use and the daemon self-upgrades in place — and verifies it against the release's `checksums.txt`. npm's global bin provides the PATH'd `autter` command through a launcher that execs the native binary.
- Package version is stamped from the release tag at publish time (`npm i -g autter@X.Y.Z` ↔ release `vX.Y.Z`); the in-repo placeholder resolves to the latest release. postinstall never fails the surrounding `npm install` — on any error it warns and defers the download to first run. Escape hatches: `AUTTER_NPM_SKIP_DOWNLOAD=1`, `AUTTER_RELEASE_TAG`, `AUTTER_NO_INSTALL_PING=1` (install-ping parity with install.sh, tagged `source=npm`).
- `release.yml` gains a `publish-npm` job that runs after the GitHub Release exists and self-skips with a notice when the `NPM_TOKEN` secret is unset, so releases never block on npm.

### `src/ci/workflow_templates/github.yaml`, `src/ci/workflow_templates/gitlab.yaml`

- The `include_str!`-embedded CI templates (what `autter ci` writes into user repos) now install from `https://api.autter.dev/install.sh`. A repo-wide sweep found no other live references to the dead URL; docs and both website repos were already migrated on 2026-08-14.

## Behaviour Guarantees

| Scenario | Before | After |
|---|---|---|
| Fresh Unix install, same terminal | "source your rc file" often didn't surface `autter` | `source "$HOME/.autter/env"` always works, printed as the last line |
| macOS bash user with both rc files | only `.bashrc` configured; login shells missed PATH | both configured; env file dedups the double-source |
| `npm i -g autter` | E404 | installs the checksum-verified release binary |
| CI generated by `autter ci` | piped marketing HTML into bash | installs from `api.autter.dev` |

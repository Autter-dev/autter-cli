# Context for agents, memory skills in the repository, and one-command MCP setup

- `autter context "<task>"` returns, in one call, what Autter knows that matters for a task: the repository's memory facts, wiki pages and code structure, ranked and cut to a token budget. It prints Markdown for an agent to read: one line per item with its source, title and path, the fact id to cite (`rmf_…`), a `more:` line saying where to read further, and a `cursor:` line. It is the same as the `get_context` MCP tool, for agents that aren't connected to the Autter MCP server.
  - It asks about the files changed in your checkout by default; name others with `--path` (repeatable) and functions or types with `--symbol`.
  - `--budget <300-16000>` sets the tokens, `--include memory,wiki,code` picks the sources, and `--since <cursor>` leaves out what an earlier call already returned unchanged. `--json` prints the raw answer.
- `autter memory skills install` writes the repository's own memory skill, generated by Autter from its memory facts, into the checkout: `.agents/skills/autter-repo-memory/SKILL.md` and a Cursor rule. Commit them and every teammate's agent has the memory, with or without the CLI. It replaces only files Autter wrote (`autter_generated: true` in their frontmatter) unless you pass `--force`. `autter memory skills preview` (or `install --print`) prints the files and writes nothing.
- `autter mcp connect` adds Autter's MCP server (`https://api.autter.dev/mcp`, or your configured API address plus `/mcp`) as `autter` to each installed agent's user-level config, and `autter mcp disconnect` removes it:

  | Agent | How |
  |---|---|
  | Claude Code | `claude mcp add --transport http --scope user`, or `mcpServers.autter` in `~/.claude.json` when `claude` isn't on PATH |
  | Codex | `codex mcp add autter --url`, or `[mcp_servers.autter]` in `~/.codex/config.toml`; then `codex mcp login autter` |
  | Cursor | `mcpServers.autter = {"url"}` in `~/.cursor/mcp.json` |
  | VS Code | `servers.autter = {"type": "http", "url"}` in the user `mcp.json` (and each profile's existing one) |
  | Gemini CLI | `mcpServers.autter = {"httpUrl"}` in `~/.gemini/settings.json` |
  | OpenCode | `mcp.autter = {"type": "remote", "url", "enabled": true}` in `~/.config/opencode/opencode.json` |

  Only the URL is written: the server signs you in with OAuth the first time an agent uses it. Agents that aren't installed are skipped, every file is backed up before it changes, comments and key order are kept, and running it again replaces the entry instead of adding a second one. `--dry-run` shows the plan and `--agent <name>` limits it.
- The `repo-memory` skill now tells agents to call `autter context` first (or `get_context` when the MCP server is connected), to cite the fact ids that change what they do, and that `autter mcp connect` connects them.

`autter context` and `autter memory skills` need the updated Autter API; on an older deployment they say so.

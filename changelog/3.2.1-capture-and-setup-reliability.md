# 3.2.1: setup you can trust, and attribution that doesn't go missing

3.2.1 fixes the ways autter said everything was fine while it wasn't capturing, and the ways correct attribution got lost or mislabelled after the fact.

## What changed

### Setup and the CLI
- Onboarding and `autter install --system` check capture end to end (background service, git trace2 config, a live git event reaching the service) before saying "You're all set". "Mode saved" and "capture verified" are reported separately, and anything unfinished comes with the command that fixes it.
- Your own `[trace2]` git settings are merged, not replaced.
- `autter doctor`, `autter whoami` and `autter status` use the same rules for "is the service healthy" and "is cloud upload on", so they no longer contradict each other.
- `-h` / `--help` prints help for every command and does nothing else. Unknown flags are rejected.
- `autter uninstall` asks first (or takes `--yes`), lists only what it actually removed, and also removes the VS Code / Cursor extension.

### Capture
- **Service down at commit time:** the commit's attribution is rebuilt from its checkpoints when the service comes back, or the git proxy writes the note itself. `autter doctor` finds and rebuilds missed commits. `checkpoint` warns when git capture isn't configured.
- **Shell edits by agents** (`echo >>`, `sed -i`, formatters) are attributed to the agent.
- **VS Code Copilot agent mode** edits are captured even when VS Code sends no transcript path. `autter doctor` shows whether Copilot hooks are installed and when the last Copilot edit was captured.
- **Cloud-agent detection** reads the committing command's environment, not the background service's. A stray `CLOUD_AGENT_*` variable can no longer credit every human edit on the machine to an agent.

### Attribution after rewrites
- AI lines keep their attribution through `git mv`, rebase (including onto a branch that renamed the file), cherry-pick ranges, `cherry-pick -n` + `git commit`, a conflicted cherry-pick finished with `git commit`, and `--continue` after a restart.
- Plain `git fetch` imports teammates' notes (`refs/notes/ai`) without overwriting yours.
- `git push` waits briefly so a just-made commit's note is pushed with it.

### Connected mode
- Connected mode writes local git notes as well as syncing to the dashboard. Existing connected setups switch over automatically.
- Notes from before this release that were only in the upload queue are copied into `refs/notes/ai` once per repository. `autter notes backfill` does it on demand.

## Checking it

```bash
autter upgrade            # or: npm install -g @autter/cli@latest
autter --version          # 3.2.1
autter doctor             # every check should pass; anything else names its fix
```

In a scratch repo, with an AI agent (Claude Code, Cursor, Copilot in VS Code):

1. Ask the agent to add a few lines with its edit tool, and one more with a shell command (`echo "x" >> file.txt`). Add one line yourself. Commit.
2. `autter blame file.txt` shows the agent's lines (shell one included) as AI and yours as human. `autter stats HEAD` agrees.
3. `git mv file.txt moved.txt && git commit -m mv`, then `autter blame moved.txt`. The attribution is unchanged.
4. `autter bg shutdown`, make an agent edit and commit, then `autter bg start` (or `autter doctor`). `autter stats HEAD` shows the AI lines.
5. `autter uninstall --help` prints help and changes nothing.
